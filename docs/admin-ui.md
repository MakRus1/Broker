# Админка Configs

React-приложение лежит в `frontend/admin`, BFF на userver — в `services/admin_bff`.
Браузер работает только с BFF на одном origin; access/refresh token остаются на сервере.
Keycloak выполняет пользовательский вход; Configs проверяет права на каждую операцию.

## Запуск

```sh
make local-up
```

Откройте http://localhost:13080. Вход через Keycloak:
`author` имеет read/write, `reviewer` — read/approve. Пароли находятся в
`.local/auth-secrets.json`, поля `author-password` и `reviewer-password`.
Это локальные учетные записи из realm `broker`, не администратор master.

Node.js на хосте для этого запуска не нужен: production-сборка интерфейса выполняется
в закрепленном Node 24 контейнере, результат хранится в volume `admin-ui`.
BFF отдает HTML/JS/CSS с того же origin. Локальный стек сохраняет существующие БД.
Для уже созданного realm отдельная идемпотентная задача обновляет только callback
и post-logout URL клиента `broker-admin`. Она использует локального bootstrap admin;
если он удален или пароль изменен, обновите клиент через постоянного администратора.
Импорт realm сам по себе существующие настройки не перезаписывает.

## Рабочий сценарий

1. Войдите как `author`, откройте конфиг и нажмите «Редактировать».
2. Измените JSON, опишите причину и нажмите «Готово». До этого момента серверного
   драфта нет; невалидный JSON или значение по схеме не сохранятся.
3. Выйдите, завершите выход в Keycloak и войдите как `reviewer`.
4. Откройте тот же конфиг: сравните исходное и предложенное значение,
   подтвердите драфт. Подтверждение сразу публикует его.

Автор может изменить или отменить свой активный драфт, но не подтвердить его.
Строка каталога кликабельна целиком. Каталог занимает всю страницу; конфиг открывается в панели справа с вкладками
«Значение» и «История». Клик снаружи панели, крестик и Escape возвращают к каталогу.
При несохранённом значении или причине нужно подтвердить потерю изменений; открытие
редактора без изменений не вызывает предупреждения. Перетаскивание из панели наружу
не закрывает её. Та же защита действует при отмене редактирования.
Редактор заменяет просмотр значения. Причина изменения
обязательна; без изменения значения «Готово» недоступна. Пробелы и порядок ключей
JSON не считаются изменением. Возврат драфта к опубликованному значению также
запрещен: ненужный драфт следует отменить. Configs отклоняет такие значения и через API.
JSON-редактор на CodeMirror загружается при переходе к редактированию. Объекты и
массивы сворачиваются стрелками слева, доступны «Свернуть всё» и «Развернуть всё».
Сворачивание не меняет значение; работают отмена/повтор изменений.
В JSON-редакторе Tab вставляет два пробела, Shift+Tab уменьшает отступ, в том числе
для выделенных строк. Escape, затем Tab возвращает переход между полями.
Ошибки показываются уведомлением справа сверху, ошибки JSON — также возле редактора.
Diff выделяет добавленные, удаленные и измененные поля, массивы сравниваются по индексам.

История показывает до 100 последних драфтов конфига и события выбранного драфта.
Строка истории кликабельна целиком; с клавиатуры запись открывается кнопкой номера драфта.
При выборе записи список заменяется подробностями и двусторонним diff на всю область
панели. «Назад к истории» возвращает список. Слева исходное значение, справа новое;
удаленные строки подсвечены красным, добавленные — зеленым. Неизмененные участки
из трех и более строк свернуты, вокруг изменений остаются две строки контекста.
Каждый участок раскрывается и сворачивается отдельно. Неизмененные строки
сохраняют контекст; большие документы сравниваются с ограничением памяти.

У опубликованного драфта доступна кнопка «Откатить»: она подставляет значение этой
версии в редактор нового драфта с diff относительно текущего значения. Проверьте
результат, укажите причину и сохраните; потребуется подтверждение другого пользователя.
При активном драфте откат недоступен. Если значение уже совпадает с текущим, кнопка
отключена. Более старые драфты за пределами последних 100 пока можно получить через API.

Имена автора и подтвердившего сохраняются из проверенного токена вместе с драфтом.
Идентификатор `issuer#subject` используется для проверки прав и доступен в подсказке.
У старых записей без имени показывается «Имя недоступно» (либо имя текущего пользователя,
если это его запись). Имя нельзя передать через тело административного запроса.
При конфликте версий сохранение не повторяется автоматически: отмените локальное
редактирование, обновите данные и проверьте изменения перед новой попыткой.
Новый драфт при уже активном не создается.

## Разработка и проверки

Требуются Node.js 24 и pnpm 11.25.0. Версии зависимостей и lock-файл закреплены.

```sh
cd frontend/admin
pnpm install --frozen-lockfile
pnpm dev
pnpm check-format
pnpm test
pnpm build
```

Для `pnpm dev` сначала освободите порт 13080 и запустите BFF на 13081
в отдельном терминале из корня репозитория:

```sh
docker compose -f .local/compose.yaml stop admin_bff
docker compose -f .local/compose.yaml run --rm --no-deps -p 127.0.0.1:13081:8180 admin_bff
```

После этого запустите `pnpm dev` из `frontend/admin`. Внутри BFF остаются те же
`admin-origin: http://localhost:13080` и OIDC callback. Vite проксирует `/api` и `/auth`
на 13081; клиентские токены не появляются в браузере. Обычный `make local-up`
использует готовую сборку и не запускает Vite.

`src/main.tsx` только монтирует приложение. `App.tsx` задает композицию страницы,
`components/` содержит отдельные экран входа, каталог, панель конфига, редактор, просмотр значения,
драфт и историю. `hooks/useWorkspace.ts` управляет загрузкой и действиями,
`api.ts` — HTTP и типами. JSX не содержит реализации HTTP-запросов.
BFF выдает для каждой HTML-страницы уникальный CSP nonce, который CodeMirror
использует для своих стилей. Скрипты разрешены только с собственного origin.
Prettier проверяет HTML, JSON, TS/TSX и CSS в CI; `pnpm format` исправляет оформление.
`node_modules`, `dist`, coverage и `.pnpm-store` не отслеживаются Git.

Функциональные тесты BFF проверяют настоящие подписи JWT, state/nonce/PKCE,
одноразовый callback, CSRF, серверные сессии, обновление/отзыв токенов и ошибки
типизированного клиента. Мокаются только Keycloak endpoints и Configs.
Общие временные RSA-ключи для тестов находятся в `tests/support/auth_tokens.py`.

## Границы первого этапа

Сессии пока находятся в памяти одной реплики, абсолютный срок — 8 часов.
После перезапуска нужен повторный вход. Перед несколькими репликами потребуется
общее хранилище сессий; это отдельный инфраструктурный шаг.
Выход локально уничтожает сессию сразу, отзыв refresh token выполняется по возможности,
затем браузер проходит стандартный выход Keycloak. Back-channel logout пока нет;
отзыв роли/сессии вне админки учитывается при истечении access token и обновлении.

Для production обязательны HTTPS issuer/endpoints/origin и Secure cookie.
HTTP разрешен только для localhost в dev-конфигурации. Клиент `broker-admin`
использует PKCE без password grant. В BFF нет локальных пользователей или паролей.
Расширенные редакторы по схемам, поиск/пагинация истории, аудит с правилами хранения
и права на компании/бизнес-сущности остаются отдельными задачами.

## Реализация API BFF

JSON-маршруты `/api/session`, `/api/logout` и `/api/configs/...` описаны OpenAPI
в `services/admin_bff/docs/api/api`. Для них генерируются обработчики, модели и
валидация. Каждая ручная view вызывает конкретный метод клиента Configs.
`components/browser_session` проверяет сессию, Origin и CSRF до разбора JSON,
создает снимок личности и обрабатывает ошибки upstream. Проверка прав на конфиги
остается в Configs. Отдельные HTTP-обработчики обслуживают вход, callback и статику.
Новые API следует добавлять через спецификацию и `make gen`.
