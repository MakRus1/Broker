# Компоненты Contracts

HTTP-ручки проверяют права, извлекают организацию, автора и токен и явно вызывают
операции компонентов. RequestContext не передаётся в компоненты.

| Компонент | Ответственность |
| --- | --- |
| ContractsComponent | Подготовка договора, проверка сторон и банковских счетов, чтение и сохранение, реестр и фильтры, выделение номера и запись истории |
| NumberingComponent | Проверка администратора указанной организации, чтение и изменение настроек нумерации |

В сценарии сохранения view вызывает PrepareContract, затем SaveContract.
Подготовка нормализует и проверяет ввод, получает стороны и банковские счета
через клиента контрагентов и возвращает ContractRaw. Сетевые вызовы завершаются
до транзакции записи. Выделение номера, сохранение договора и история фиксируются
одной транзакцией. Конфликт редакций проверяется при записи.

В административных ручках RequireAdministrator вызывается явно перед чтением
или изменением настроек. Компонент получает организацию и токен, проверяет доступ
через клиент организаций и преобразует ожидаемые ошибки. Корневой администратор
и управление именно указанной организацией проверяются сервисом организаций.

Методы FindContract, ListContracts и GetContractFilterValues принимают организацию
явно. Реестр сохраняет read-only транзакцию для SET LOCAL и курсорную пагинацию.
Результаты реестра, строка SQL и NumberingRow находятся в models, по одному типу
в файле. Только composite-тип ContractRaw находится в models/pg.

Чистые преобразования PostgreSQL ↔ API находятся в converters/contracts.hpp
и converters/numbering.hpp. Метаданные реестра — в registry/fields.hpp. В helpers
остаётся чтение настроек нумерации с обработкой отсутствующей записи. Анонимный
namespace расположен перед именованным. Блоки операций разделены пустыми строками.

HTTP API, SQL, миграции, правила валидации, коды ошибок и границы транзакций
сохранены. Регрессионная проверка охватывает права, изоляцию организаций, стороны,
банковские счета, фильтры, пагинацию, нумерацию и конфликты редакций.
