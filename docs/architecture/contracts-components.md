# Компоненты Contracts

HTTP-ручки проверяют права, извлекают организацию, автора и токен и явно вызывают
операции компонентов. RequestContext не передаётся в компоненты.

| Компонент | Ответственность |
| --- | --- |
| ContractsComponent | Проверка сторон и банковских счетов, чтение и атомарное сохранение договора с номером и историей |
| ContractRegistry | Страница реестра, курсорная пагинация и значения фильтров |
| NumberingComponent | Проверка администратора указанной организации, чтение и изменение настроек нумерации |

В сценарии сохранения view нормализует и проверяет карточку чистой функцией
helpers::NormalizeAndValidateContract, преобразует её через converters::Convert,
проверяет стороны через ContractsComponent::ValidateContractParties и вызывает
SaveContract. Проверка сторон использует клиент контрагентов. Сетевые вызовы
завершаются до транзакции записи. Выделение номера, сохранение договора и история
фиксируются одной транзакцией. Конфликт редакций проверяется при записи.

В Deps компонент договора называется contracts, компонент реестра — registry.
Имена регистрации: contracts-contracts и contracts-registry. В ContractsComponent
нет SQL фильтрации и пагинации; ContractRegistry не проверяет стороны и не изменяет
договоры. Чистая проверка карточки находится в helpers/contract_validation и не
регистрируется как компонент userver. Отдельного слоя domain нет.

В административных ручках RequireAdministrator вызывается явно перед чтением
или изменением настроек. Компонент получает организацию и токен, проверяет доступ
через клиент организаций и преобразует ожидаемые ошибки. Корневой администратор
и управление именно указанной организацией проверяются сервисом организаций.

Метод FindContract принадлежит ContractsComponent; ListContracts и
GetContractFilterValues — ContractRegistry. Все принимают организацию явно.
Реестр сохраняет read-only транзакцию для SET LOCAL и курсорную пагинацию.
Результаты реестра, строка SQL и NumberingRow находятся в models, по одному типу
в файле. Только composite-тип ContractRaw находится в models/pg.

Чистые преобразования PostgreSQL ↔ API находятся в converters/contracts.hpp
и converters/numbering.hpp. Метаданные реестра — в registry/fields.hpp, построение SQL — в registry/contract_query.hpp. В helpers
остаётся чтение настроек нумерации с обработкой отсутствующей записи. Анонимный
namespace расположен перед именованным. Блоки операций разделены пустыми строками.

HTTP API, SQL, миграции, правила валидации, коды ошибок и границы транзакций
сохранены. Регрессионная проверка охватывает права, изоляцию организаций, стороны,
банковские счета, фильтры, пагинацию, нумерацию и конфликты редакций.
