# Компоненты Counterparties

HTTP-ручки явно проверяют права, извлекают организацию, автора и токен и вызывают
операции компонентов. Компоненты не принимают RequestContext.

| Компонент | Ответственность |
| --- | --- |
| CounterpartiesComponent | Карточки, проверка логиста через организации, дубликаты, архив и история |
| CounterpartyRegistry | Страница реестра, курсорная пагинация и значения фильтров |
| BankAccountsComponent | Банковские реквизиты, основные счета, ограничения владельца и сохранение с аудитом |
| DaData | Получение реквизитов по ИНН, проверка ответа внешнего сервиса и обработка недоступности |

В Deps используются имена counterparties, registry и bank_accounts. Методы имеют
предметные имена: CreateCounterparty, UpdateCounterparty, FindCounterparty,
SetCounterpartyArchived, GetCounterpartyHistory, ListCounterparties,
GetCounterpartyFilterValues, SaveBankAccount и ListBankAccounts.

При создании view преобразует ввод, нормализует и проверяет карточку чистой функцией,
при необходимости проверяет логиста и вызывает атомарное создание. При частичном
обновлении проверка логиста также видна во view; применение изменения и проверка
итоговой карточки остаются под блокировкой текущей записи, поскольку требуют
сохранённых значений. HTTP-вызовов внутри транзакции нет.

Чистые правила карточки и банковского счёта находятся в helpers/counterparty_validation
и helpers/bank_account_validation. Это свободные функции, а не DI-компоненты.
Конвертеры карточек, счетов, истории и DaData находятся в converters. Метаданные
реестра — в registry/fields.hpp, конструктор SQL — в registry/query.hpp. Строка
SQL и результаты реестра находятся в models; composite-типы — в models/pg.
Анонимный namespace расположен перед именованным, логические блоки разделены.

Сохранён порядок блокировок идентификатора и реквизитов карточки. Изменения счетов
сериализуются блокировкой владельца, как и архивирование карточки. Аудит фиксируется
одной транзакцией с изменением данных. Повтор создания с прежним UUID остаётся
идемпотентным. Реестр использует согласованное чтение и прежние курсоры.

SQL, миграции, права, HTTP API, правила реквизитов, история и границы транзакций
сохранены. Проверка — полный testsuite Counterparties, включая контакты, счета,
дубликаты, повторы, архив, историю, фильтры, права и DaData.
