# Компоненты Counterparties

Компонент объединяет определённую ответственность, а не только бизнес-логику.
В сервисе используются два компонента карточек и счетов и существующий
технический компонент интеграции DaData.

| Компонент | Ответственность |
| --- | --- |
| CounterpartiesComponent | Карточки, нормализация и валидация реквизитов и контактов, проверка логиста, дубликаты, архив, реестр и история |
| BankAccountsComponent | Банковские реквизиты, основные счета, ограничения владельца и сохранение с аудитом |
| DaData | Получение реквизитов по ИНН, проверка ответа внешнего сервиса и обработка недоступности |

Компоненты получают только необходимые зависимости через ComponentContext;
общий ResolveDeps остаётся адаптером HTTP-слоя. Преобразования моделей карточек,
банковских счетов, событий истории и ответа DaData находятся в converters.
Метаданные реестра — в registry/fields.hpp, общий конструктор запросов API
и изолированного бенчмарка — в registry/query.hpp. В helpers остаются совместно
используемые нормализация необязательного текста и запись аудита.

Проверка логиста выполняется до транзакции. Сохранён порядок блокировок
идентификатора и реквизитов карточки. Изменения счетов сериализуются блокировкой
владельца, как и архивирование карточки. Аудит фиксируется одной транзакцией
с изменением данных. Повтор создания с прежним UUID остаётся идемпотентным.

Запрос значений фильтра получил именованную схему. SQL, миграции, права, API,
правила реквизитов, история и границы транзакций сохранены. Проверка — полный
testsuite Counterparties, включая контакты, счета, дубликаты, повторы, архив,
историю, фильтры, права и DaData.
