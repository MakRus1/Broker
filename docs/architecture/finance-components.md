# Компоненты Finance

Views явно собирают HTTP-сценарий: извлекают организацию, пользователя и токен,
проверяют права, получают связанные документы и передают подготовленные данные
компонентам. Компоненты не принимают RequestContext и не владеют клиентами
других бизнесовых сервисов.

| Компонент | Ответственность |
| --- | --- |
| FinancialLabelsComponent | Сохранение меток и истории, чтение реестра и значений фильтров |
| ServiceChargesComponent | Атомарное сохранение и импорт услуг, пересчёт связанных счетов, сводка |
| InvoicesComponent | Счета, включение и перепривязка услуг, нумерация и хранение печатных снимков |
| PaymentsComponent | Поступления и списания, распределение оплаты, остатки и подбор документов |
| SettlementsComponent | Согласованное чтение задолженности, просрочки и акта сверки |
| SettingsComponent | Чтение и сохранение настроек организации |
| FinancialHistoryComponent | Чтение истории и построение структурированных изменений |
| ExchangeRates | Технический компонент получения и хранения курсов ЦБ |

Компоненты хранения получают PostgreSQL. ServiceChargesComponent также использует
ExchangeRates для переиспользуемого расчёта сводки: курсы загружаются после закрытия
транзакции чтения. При сохранении услуги курс выбирает view до транзакции записи.

## Размещение кода

В `models/pg` находятся только модели PostgreSQL composite-типов. Именованные
результаты SQL-запросов, страницы реестров и данные операций находятся в `models`,
по одной модели в файле. Чтение использует AsSingleRow, AsSetOf и pg::kRowTag.

В `converters` находятся преобразования входных моделей, PG-моделей и печатных
реквизитов. Они не получают HTTP-контекст и не выполняют внешние запросы.
В `registry` находятся поля и построение запросов реестров. В `helpers` остаются
переиспользуемые проверки сторон, расчёты сумм, чтение настроек и операции
изменения счёта внутри переданной транзакции. Анонимные пространства имён
расположены перед именованными.

## Границы операций

Сохранение счёта и платежа начинается во view с подготовки модели и проверки
сторон, счетов сторон и договора. Компонент затем атомарно сохраняет документ,
связанные услуги или распределения и историю.

При сохранении услуги view проверяет поставку или перевозку, контрагента и договор.
Метка повторно читается внутри транзакции сохранения услуги. Право изменения
счёта передаётся отдельно и проверяется, если под блокировкой обнаружена привязка
или запрос создания услуги из счёта. Поэтому услуга без счёта не требует прав
управления счетами.

Порядок блокировок сохранён: услуга, затем связанные счета; при распределении
оплаты — платёж, затем счета в общем порядке. HTTP-вызовов внутри этих транзакций нет.

Печать счёта разделена на чтение снимка редакции и его сохранение. Если готового
снимка нет, view получает реквизиты вне транзакции. Перед записью снимка компонент
под блокировкой повторно проверяет редакцию; при одновременном создании снимка
возвращает сохранённый результат.

Внутренний импорт использует организацию из команды и проверенную сервисную
идентичность. Провайдер автора сверяется с идентичностью вызывающего сервиса.
Регистрация команды, услуги и история сохраняются одной транзакцией; повтор
проверяет исходное содержимое команды.

Права на историю проверяет view. FinancialHistoryAccess передаёт разрешения
просмотра связанных событий и номеров счетов именованными полями: отсутствие права не раскрывает связанные документы.
Исторические JSONB-снимки преобразуются в типизированные Snapshot и DocumentSnapshot;
старые отсутствующие поля не заменяются текущими значениями.

Сводка SQL возвращает одну строку на валюту: отдельные итоги услуг поставки,
её перевозок и общий итог. Отсутствующая группа представлена NULL; существующая
группа с нулевыми суммами сохраняется. Числовых кодов групп нет.

Чтение настроек обрабатывает отсутствие записи, а ToFinanceSettings преобразует
только FinanceSettingsRow без обращения к ResultSet.

Пути API, JSON-контракты, миграции и бизнесовые правила не меняются.
Регрессионные проверки охватывают услуги и импорт, счета, распределение платежей,
запрет редактирования оплаченных документов, права, историю, курсы, задолженность,
сверку, печатные снимки и отказ справочника без частичного сохранения документа.

Общие транзакционные операции счетов находятся в `components/invoice_operations`.
Модуль получает транзакцию сценария: загрузка счёта, проверка привязки,
включение и исключение услуги не создают отдельных транзакций.
Пересчёт сумм счёта выполняется одной функцией по снимкам включённых услуг;
она используется также при изменении услуги и сохранении полного состава счёта.
