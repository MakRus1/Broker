# Компоненты Notifications

| Компонент | Ответственность и зависимости |
| --- | --- |
| EventAcceptanceComponent | Приём событий, проверка получателя, дедупликация и атомарная запись уведомлений; PostgreSQL |
| InboxComponent | Список, прочтение и очистка личных уведомлений с проверкой доступа; PostgreSQL и клиент Organizations |

HTTP-ручки передают типизированные модели компонентам и формируют ответы.
Компоненты получают только свои зависимости из ComponentContext.
Преобразования строк PostgreSQL в уведомления и payload событий в общую модель
доставки находятся в converters. NotificationDelivery — внутренняя модель, не DTO ручки.

Приём события и создание личного уведомления остаются в одной транзакции.
Повтор с тем же содержимым успешен, с другим содержимым возвращает конфликт.
Проверка issuer выполняется до транзакции. Правила исключения автора из получателей
сохранены, включая уведомление менеджера об ошибке создания поставки.
Авторизация служебного клиента остаётся в middleware.

Inbox проверяет доступ к организации через Organizations перед чтением и изменением.
Получатель определяется проверенным токеном; ограничение по организации, issuer и
subject, пагинация и предел размера выборки сохранены. SQL и миграции не меняются.

Проверка — полный testsuite Notifications: варианты событий, повторы и конфликты,
авторизация, получатели, пагинация, прочтение и очистка.
