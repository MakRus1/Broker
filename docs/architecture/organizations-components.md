# Компоненты Organizations

Компоненты объединяют ответственность и зависимости; это относится как к
управлению организациями, так и к технической интеграции с Keycloak.

| Компонент | Ответственность |
| --- | --- |
| OrganizationsComponent | Создание, изменение и административный реестр организаций |
| MembersComponent | Добавление, создание и изменение сотрудников, доступ и профиль, идемпотентный provisioning |
| RolesComponent | Роли организации, каталог разрешений и защита последнего администратора |
| AccessComponent | Членство, проверка разрешений организации и платформы, административный доступ и справочник сотрудников |
| RegistryDefaultsComponent | Виды реестров по ролям и управление их редакциями |
| PermissionReleasesComponent | Регистрация, активация и сверка версий каталогов прав |
| Users | Техническая интеграция с Keycloak Admin API, создание и поиск пользователей, изменение профиля |

HTTP-ручки вызывают операции компонентов и формируют ответы. Компоненты получают
только необходимые зависимости из ComponentContext, без общего ResolveDeps.
Модели анонимных запросов и результатов получили имена; компоненты не зависят
от DTO HTTP-ручек. Развёрнутые JSON-контракты всех 25 операций сохранены.

Чистые преобразования PostgreSQL, пользователей Keycloak, видов реестров и
каталогов прав находятся в converters. Модель User отделена от компонента Users.
Общие запросы административных реестров находятся в registry/admin.hpp.
В helpers остаются совместно используемые проверки администратора, ролей,
зависимостей разрешений, типов ошибок и запись аудита. Валидация каталогов релизов
и видов реестров находится в реализации соответствующих владельцев.

Границы доступа и транзакций сохранены. Проверка членства не заменяет проверку
разрешения. Изменение сотрудников и ролей сохраняет блокировку организации и
защиту последнего администратора. Внешние вызовы Keycloak при создании и изменении
профиля выполняются вне транзакций PostgreSQL. Создание сотрудника сохраняет
проверку идентификатора запроса и записанного намерения до внешнего вызова и
повторную проверку доступа после него. Аудит фиксируется вместе с изменениями.
Каталоги прав неизменяемы в пределах версии, циклы и зависимости проверяются
до регистрации. SQL, миграции и бизнесовые правила этим рефакторингом не меняются.

Регрессионная проверка — полный testsuite Organizations: членство, права,
организации, роли, сотрудники, Keycloak, последний администратор, provisioning,
платформенный доступ, реестры, виды ролей и жизненный цикл каталогов прав.
