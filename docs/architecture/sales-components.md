# Компоненты Sales

Бизнесовые сценарии сервиса собраны в компонентах `services/sales/src/components`.
Ручки получают типизированный запрос, вызывают операцию и формируют HTTP-ответ.
Проверки разрешений endpoint остаются в сгенерированном HTTP-слое. Проверки
связанных объектов, редакций и бизнесовых переходов выполняет компонент.

| Компонент | Ответственность |
| --- | --- |
| CardsComponent | Карточка работы с клиентом, этап, следующее действие, история и реестр |
| ContactsComponent | Контакты и исправления, актуализация следующего действия карточки |
| InquiriesComponent | Входящие запросы, номера, история и постановка создания поставки |
| ProposalsComponent | Расчёт предложения, согласование, снимки цен и история |
| RfqComponent | Запросы ставок, котировки поставщиков и разрешение их неизменяемых версий |
| SettingsComponent | Настройки организации, этапы продаж и шаблон номера запроса |
| ShipmentDispatcher | Доставка команды создания поставки, перенос услуг и уведомления |

Компоненты получают только необходимые клиенты и PostgreSQL из ComponentContext.
ProposalsComponent дополнительно использует RfqComponent. Ни один компонент не
вызывает ResolveDeps: он собирает зависимости HTTP-ручек и не участвует в
конструировании бизнесовых компонентов.

SQL исполняется внутри соответствующей операции. Границы транзакций сохранены:
проверки внешних справочников проходят перед транзакцией, изменения состояния,
история и постановка outbox фиксируются вместе. Сетевую доставку выполняет
ShipmentDispatcher после коммита.

В `helpers` остаются функции, которые используются несколькими компонентами:
чтение настроек и снимков предложений, проверка клиента и сотрудника,
блокировка редактируемого запроса. Код с одним владельцем находится в его `.cpp`:
проверка этапов и прав администратора — в SettingsComponent, проверка выбранного
этапа карточки — в CardsComponent, разрешение ссылок создаваемой поставки —
в InquiriesComponent. Расчёт предложения и перенос услуг также находятся
в реализации владельцев. Метаданные реестров находятся в `registry/fields.hpp`,
описания команд outbox — в `events/shipment_command.hpp`.

Рефакторинг не меняет OpenAPI, SQL, права доступа, расчёты и правила переходов.
Регрессионные проверки — существующий testsuite Sales: карточки, контакты,
запросы, предложения, RFQ, создание поставки и доставка уведомлений.
