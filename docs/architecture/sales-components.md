# Компоненты Sales

HTTP-сценарии находятся во views. Обработчик извлекает организацию, автора и токен
из проверенного контекста, загружает необходимые данные, обращается к клиентам
справочников и вызывает операцию сохранения. Компоненты не получают RequestContext.

| Компонент | Ответственность |
| --- | --- |
| CardsComponent | Сохранение и чтение карточки клиента, проверка этапа, история |
| ContactsComponent | Контакты, исправления и атомарное обновление следующего действия карточки |
| InquiriesComponent | Входящие запросы, выделение номера, история, подготовка и постановка команды создания поставки |
| ProposalsComponent | Подготовка котировок и данных расчёта, атомарное сохранение предложения, согласование и история |
| RfqComponent | Подготовка связанных данных RFQ, сохранение и история, чтение конкретной версии |
| SalesRegistry | Страницы реестров карточек и запросов, курсоры и значения фильтров |
| SettingsComponent | Чтение и атомарное изменение настроек, проверка этапов и шаблона номера |
| ShipmentDispatcher | Доставка команды создания поставки, перенос согласованных услуг и уведомления |

Зависимости компонентов следуют их ответственности. ProposalsComponent использует
RfqComponent, Finance и контрагентов для подготовки расчёта. Диспетчер получает
клиентов, служебные токены и outbox, необходимые для доставки. Отдельного
универсального компонента справочников нет. Прямые HTTP-вызовы во views допустимы,
если они помогают понять сценарий.
Проверка администрирования указанной организации и дополнительного права создания
поставки выполняется во views до чтения и изменения данных.

## Предложение

View читает входящий запрос, преобразует и проверяет ввод, вызывает подготовку
расчёта, чистый расчёт и сохранение. ProposalsComponent::PrepareProposalCalculation
для строк со ссылками на котировки загружает конкретную версию RFQ и подставляет
снимок закупки в переданный input через rfq_rules::ApplyQuote. Метод получает
метки, поставщиков и курсы, переиспользуя уже загруженные данные в пределах вызова.
Он не начинает транзакцию записи. proposal_rules::CalculateProposal принимает
подготовленный input и типизированные данные и считает результат без БД,
сетевых клиентов и DI.

При сохранении ProposalsComponent блокирует запрос, повторно проверяет редакцию,
доступность редактирования и участки маршрута. Предложение и история фиксируются
вместе. Если запрос изменился во время расчёта, результат не сохраняется.

## RFQ и создание поставки

View RFQ читает входящий запрос, преобразует и проверяет ввод чистой функцией,
вызывает PrepareRfq и сохранение. RfqComponent получает клиента и ответственного,
проверяет поставщиков и метки, подставляет их названия в котировки. Клиенты
контрагентов, организаций и Finance подключены через DI. Повторные поставщики и
метки загружаются один раз в пределах подготовки. Сетевые вызовы завершаются
до транзакции записи. При сохранении компонент под блокировкой запроса проверяет доступность
редактирования, участок и редакцию; сохраняет RFQ, историю и события уведомлений.

View создания поставки проверяет право, читает запрос и возвращает уже запущенную
операцию. Затем вызывает PrepareShipmentCreation и StartShipmentCreation.
InquiriesComponent при подготовке получает клиента и логиста, собирает ссылки
маршрута чистой функцией, загружает транспортные пункты и проверяет контрагентов.
Клиенты контрагентов, организаций и транспортных пунктов подключены через DI;
подготовка возвращает типизированный ShipmentCreationContext и завершается
до транзакции постановки команды.
InquiriesComponent под блокировкой повторно проверяет запрос, редакцию и согласование.
Команда и запись outbox сохраняются вместе. ShipmentDispatcher доставляет её после
коммита. Повторная постановка возвращает текущее состояние операции.

## Размещение кода

В components находятся зарегистрированные компоненты и чистые функции с предметной
ответственностью: proposal_calculation, rfq_rules и shipment_route. Чистые функции
не регистрируются в ComponentList и не владеют зависимостями.

В models находятся составные результаты запросов и данные операций; в models/pg —
PostgreSQL composite-типы. В converters — преобразования входных моделей, настроек,
команды поставки и импорта услуг. registry/fields.hpp содержит метаданные реестров
и построение фильтров. В helpers остаются разделяемые операции чтения предложения, настроек
с обработкой отсутствующей записи и блокировки редактируемого запроса. Конвертер
настроек принимает PG-модель и не работает с ResultSet. Анонимные пространства имён расположены перед
именованными; операции разделены на логические блоки.

Пути API, SQL, права, расчёты, переходы и границы транзакций сохраняются.
