# Компоненты Sales

HTTP-сценарии находятся во views. Обработчик получает организацию и автора из
проверенного HTTP-контекста, проверяет дополнительные права, загружает необходимые
данные, обращается к справочникам и вызывает операцию компонента. Компоненты не
получают RequestContext и не извлекают из него пользователя или токен.

| Компонент | Ответственность |
| --- | --- |
| CardsComponent | Сохранение и чтение карточки клиента, проверка этапа, история |
| ContactsComponent | Запись и исправление контакта, атомарное обновление следующего действия карточки |
| InquiriesComponent | Входящие запросы, выделение номера, история и постановка команды создания поставки |
| ProposalsComponent | Сохранение рассчитанного предложения, переходы согласования и история |
| ProposalCalculator | Расчёт цен и итогов предложения с курсами, финансовыми метками и неизменяемыми версиями котировок |
| RfqComponent | Хранение запросов ставок и истории, разрешение строки конкретной версии котировки |
| SalesRegistry | Страницы реестров карточек и запросов, курсоры и значения фильтров |
| SalesDirectory | Проверка клиентов и сотрудников, получение канонических данных маршрута и котировок из внешних справочников, проверка администрирования организации |
| SettingsComponent | Чтение и атомарное изменение настроек, проверка этапов и шаблона номера |
| ShipmentDispatcher | Доставка команды создания поставки, перенос согласованных услуг и уведомления |

У компонентов хранения есть только кластер PostgreSQL. Калькулятор использует RFQ
и внешние справочники, но не сохраняет результат. SalesDirectory — технический
компонент работы с внешними данными; принимает организацию и токен явно. Проверка
администрирования выполняется во view до чтения настроек указанной организации.
Право создания поставки дополнительно проверяется во view постановки команды.

## Сценарий предложения

View читает входящий запрос, передаёт его снимок калькулятору и вызывает сохранение.
Калькулятор разрешает котировки и справочники до транзакции. При сохранении компонент
блокирует запрос, повторно проверяет его редакцию, доступность редактирования и
участки маршрута. Предложение и его история фиксируются вместе. Если запрос изменился
во время расчёта, рассчитанный результат не сохраняется.

## Создание поставки

View читает запрос, получает клиента и логиста, разрешает транспортные пункты и
контрагентов маршрута. InquiriesComponent под блокировкой повторно проверяет запрос,
редакцию и согласование. Типизированный конвертер строит команду, которая сохраняется
вместе с записью outbox. Повторная постановка уже выполняемой или завершённой команды
возвращает текущее состояние. ShipmentDispatcher доставляет её после коммита.

## Размещение кода

В `models` находятся составные результаты запросов и контексты операций;
в `models/pg` — PostgreSQL composite-типы. В `converters` — преобразования входных
моделей, настроек и команды поставки. `registry/fields.hpp` содержит метаданные
реестров и построение фильтров. В `helpers` остаются разделяемые операции чтения
предложения и блокировки редактируемого запроса. Анонимные пространства имён
расположены перед именованными; операции разделены на логические блоки.

Пути API, SQL, права, расчёты, переходы и границы транзакций сохраняются.
