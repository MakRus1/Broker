# Общие морские и авиационные участки

Shipments владеет структурой маршрута и деталями моря/авиа. Стабильный ID участка
связывает его с перевозками. Transportations получает детали через
`transportation-contexts` при чтении карточки/реестра: изменение поставки видно
во всех её перевозках без обновления каждой записи. В локальный документ участка
перевозки морские/авиационные детали не записываются. Снимки аудита могут их
содержать для отображения истории.

Море: POL/POD из общего справочника портов; терминалы отправления и назначения
из контрагентов организации; ETA; фактическая дата выхода судна; судно и рейс
как текст. Авиа: аэропорты отправления и назначения; перевозчик; номер рейса;
ETD/ETA; фактические даты убытия и прибытия. Все даты календарные, без времени.
Плановые даты допускают будущее, фактические ограничены сегодняшним бизнесовым
днём Europe/Moscow, нижняя граница — 01.01.1900. Отправление не позже прибытия.

Справочник портов/аэропортов общий для организаций, хранится в Shipments и ведётся
корневым администратором платформы. UUID идентифицирует запись; код необязателен,
пара страна/код уникальна в пределах вида справочника. Архивирование скрывает
запись из выбора, сохраняя её снимки в маршрутах. Новая привязка к архивной записи
запрещена. Название/страна/код при выборе берутся из БД, а не из запроса клиента.
Внешние источники и автоматическое обновление справочников пока не подключены.

Хранение типизировано: `shipment_route_segment_v2`, `sea_details_v1`,
`air_details_v1`, `transport_location_v1`, а также новые проекции записи/чтения
поставки. Миграция V0018 переносит существующие ID и типы участков в новую
структуру. Отдельные справочники судов и рейсов в этот этап не входят.

Основные данные и маршрут существующей поставки редактируются отдельно. Маршрут
сохраняется запросом с `route_segments` и редакцией; основные поля в него не входят.
Редактирование основного раздела не отправляет `route_segments`. При создании
поставки оба раздела входят в одну команду. Переход между разделами во время
редактирования требует отказа от несохранённых изменений.

## Проверка использования при изменении маршрута

Удаление участка и изменение его типа запрещены, если в перевозках уже сохранены
его данные. Источник этой проверки — данные Transportations. Отметка регистрации
в Shipments сама по себе не доказывает использование: после регистрации сохранение
перевозки может откатиться.

Перед изменением маршрута ручка Shipments читает внутреннюю `route_usage_version`,
затем запрашивает использование участков в Transportations. При записи поставки
под блокировкой её строки проверяется, что версия не изменилась. Каждая регистрация
использования увеличивает эту версию, включая повторную регистрацию того же участка.
Это отдельный счётчик, он не меняет публичную редакцию поставки и её историю.
При изменении счётчика возвращается `409 route_usage_changed`: нужно обновить
поставку и повторить сохранение.

Transportations блокирует строку перевозки до регистрации использования и держит
блокировку до завершения записи. Проверка использования берёт совместные блокировки
строк перевозок поставки, а затем отдельным запросом в READ COMMITTED читает данные
участков. Поэтому она дожидается сохранения или отката уже начатых записей и видит
их результат. Записи, начавшиеся позже проверки, обнаруживаются по счётчику Shipments.
Если маршрут уже сохранён, регистрация по старой редакции поставки отклоняется.

Регистрация — HTTP-вызов внутри транзакции перевозки; при недоступности Shipments
запись не выполняется. Проверка использования в Shipments идёт **до** блокировки
строки поставки; Transportations не вызывает Shipments из проверки использования.
Этот порядок не создаёт встречного ожидания блокировок двух сервисов.

При обновлении работающего стенда сначала нужно обновить **все экземпляры
Transportations**, затем Shipments. Старая версия Transportations не держит нужные
блокировки. Старые отметки регистрации пока продолжают записываться для совместимости
с предыдущей версией Shipments при таком обновлении и откате; новая проверка не
использует их как постоянный запрет на изменение участка.
