# Маршрут внутри записи перевозки

Локальный замер PostgreSQL 16.14, linux/arm64, 2 CPU / 2 GB, 100 000 перевозок
(80 000 в основной организации), по 5 повторов на прогретом кеше.
В таблице — только SQL с custom plan; это не задержки HTTP под нагрузкой.

| Сценарий | p50, мс | Максимум из 5 замеров (p95), мс |
| --- | ---: | ---: |
| route_mode | 0.461 | 0.504 |
| route_station | 2.723 | 3.071 |
| route_two_groups | 8.973 | 9.499 |
| route_no_match | 0.032 | 0.038 |
| route_values | 284.010 | 288.071 |

GIN-индексы по станциям применяются к JSONB-полю записи. Проверка EXISTS сохраняет
семантику условий на один участок и нескольких групп маршрута.
Общий список вариантов станции без поиска требует обхода документов и агрегации:
около 284 мс на этом наборе. Этот сценарий следует отдельно контролировать при росте данных.

Воспроизведение: `scripts/benchmark-column-filters.py --service transportations
--rows 100000 --repetitions 5 --route --query-renderer '<transportations_registry_query_dump>'
--output /tmp/inline-routes.json`. Инструмент использует отдельную временную БД.
