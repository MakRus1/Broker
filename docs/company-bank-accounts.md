# Собственные юрлица и банковские счета

Юридические лица хранятся в Counterparties. Признак `own_company` отмечает собственное
юрлицо внутри текущей организации. Организация — рабочее пространство с сотрудниками
и правами; у неё может быть несколько собственных юрлиц. Реквизиты, контакты и логист
остаются в единственной карточке. Признак можно совмещать с существующими ролями.
В реестре есть столбец и фильтр «Собственное юрлицо»; изменение признака попадает в историю.

Вкладка «Банковские счета» доступна как для собственных юрлиц, так и для внешних
контрагентов. Счета хранятся отдельно в `bank_accounts`, с UUID, редакцией и внешним ключом
на владельца в той же организации. Договоры и финансовые записи смогут ссылаться на этот UUID.
Физическое удаление API не предоставляет. Архивирование и восстановление сохраняют UUID.

## Права

- `counterparties.read_bank_accounts` — просмотр, требует `counterparties.read`.
- `counterparties.write_bank_accounts` — изменение, требует просмотра счетов.
- Признак собственного юрлица изменяется с `counterparties.write`.

Новые права нужно выбрать у нужных ролей в админке после регистрации каталога прав.
Существующие роли автоматически дополнительных прав не получают. Сервер проверяет права
независимо от видимости вкладки. Получить банковские реквизиты через обычный `/get` нельзя.

## API

`POST /api/v1/counterparties/bank-accounts/list` принимает `counterparty_id` и возвращает
до 100 счетов владельца, включая архивные. UI по умолчанию показывает действующие.
На владельца разрешено не более 100 счетов, поэтому список ограничен без пагинации.

`POST /api/v1/counterparties/bank-accounts/save` принимает полные реквизиты счёта и
`expected_revision`: 0 при создании или текущую редакцию при изменении. Поля:
`id`, `counterparty_id`, `name`, `number`, `currency`, `bank_name`, необязательные
`bic`, `swift`, `correspondent_account`, `iban`, флаги `is_primary` и `archived`.
Необязательные реквизиты можно очищать через null. Это сохранение полной карточки,
а не PATCH: пропущенный необязательный банковский реквизит очищается.

Номер хранится без пробелов и в верхнем регистре, код валюты — три латинские буквы
в верхнем регистре. БИК — 9 цифр, SWIFT — 8 или 11 букв/цифр. Проверки существования
банка, принадлежности счёта и контрольных сумм пока нет; иностранные счета поддерживаются.

В одной валюте у владельца может быть только один действующий основной счёт и один
действующий счёт с данным номером. Чтобы назначить другой основным, сначала нужно снять
признак у предыдущего. Архивный счёт не может быть основным. У архивного владельца счета
можно читать, но нельзя изменять.

Сохранение реквизитов и запись в `business_audit` атомарны. Редакция владельца не меняется:
счета имеют независимые редакции. Аудит счетов пишется по UUID счёта; отображение его истории
в UI пока не реализовано. Конкурентные изменения владельца сериализуются короткой блокировкой;
HTTP-вызовов внутри транзакции нет. Конфликт редакции или основного счёта возвращает 409.

## Валюты и следующие этапы

UI выбирает валюту из списка Intl/CLDR с русскими названиями и поиском. В API и БД
передаётся код ISO. Существующий код, которого нет в текущей версии справочника браузера,
сохраняется доступным для редактирования.

Загрузка курсов ЦБ — следующий этап. Валюты и курсы по датам должны быть отдельными
данными; финансовая запись будет фиксировать использованный курс и его источник.
Для договорных и ручных курсов нужно сохранить отдельную возможность ввода.
