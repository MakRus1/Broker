# Драфты конфигов

Пользователь нажимает «Редактировать» в будущей админке и меняет значение в редакторе.
До нажатия «Готово» серверный драфт не создается. На «Готово» сервер проверяет схему,
обязательные поля, ограничения и предикаты. Невалидное значение возвращает 400 без
создания драфта. Другой пользователь подтверждает валидный драфт, и конфиг публикуется
в той же транзакции. Отдельных шагов отправки на проверку и публикации нет.

Сейчас реализован внутренний API и хранение; веб-интерфейс админки — следующий этап.

## Ограничения и согласованность

- Один драфт относится к одному конфигу; у конфига может быть только один активный драфт.
  Это обеспечено проверкой в транзакции и частичным уникальным индексом PostgreSQL.
- Состояния: `draft`, `published`, `cancelled`. Последние два неизменяемы и позволяют
  создать следующий драфт. Отменять или изменять активный драфт может только его автор.
- Редактирование существующего драфта тоже принимает только валидное значение.
- Каждое изменение увеличивает `version`. Подтверждение требует `expected_version`:
  правки после открытия страницы проверки не будут подтверждены по ошибке.
- У каждого конфига своя версия: изменения других конфигов не мешают подтверждению.
  Последовательность A → B → A тоже изменяет версию и считается конфликтом.
- Конфликт не публикует значение. Автор отменяет драфт и открывает редактор заново.
- Подтверждение повторно валидирует значение по текущим схемам, проверяет другого автора,
  версию конфига и драфта; затем атомарно сохраняет рабочую ревизию, закрывает драфт
  и добавляет событие. Никакой частичной публикации при ошибке не происходит.

События содержат actor, действие, снимок драфта и время. Они хранятся в БД, не в технических
логах; правила доступа и хранения полноценного пользовательского аудита определим отдельно.

## Внутренний API

Все ручки описаны в `services/configs/docs/api/admin/...` и реализованы отдельными
`src/views/admin/.../view.cpp`. Они доступны на внутреннем listener (обычно `127.0.0.1:8092`).
На публичном listener маршруты `/admin/...` отсутствуют. Экспорт клиентской спеки включает
их для будущего BFF; права доступа будут проверяться сервисом. Публичные `/configs/values` и `/configs/status` сохранены.

| Путь | Тело | Результат |
| --- | --- | --- |
| GET `/admin/configs/list` | — | `items`: каталог имен, версий и ID активных драфтов |
| GET `/admin/configs/history` | — | `items`: история опубликованных ревизий |
| POST `/admin/configs/current` | `config_name` | Рабочие `value`, `version`, `active_draft_id` |
| POST `/admin/configs/drafts/create` | `config_name`, `expected_config_version`, `value`, `description`, `actor` | 201, валидный драфт |
| POST `/admin/configs/drafts/get` | `id` | Драфт с `base_value` и предложенным `value` |
| POST `/admin/configs/drafts/list` | необязательные `config_name`, `before_id` | До 100 драфтов, новые первыми |
| POST `/admin/configs/drafts/edit` | `id`, `expected_version`, `actor`, `value` и/или `description` | Новая версия драфта |
| POST `/admin/configs/drafts/approve` | `id`, `expected_version`, `actor` | Подтверждение и публикация, `published_revision` |
| POST `/admin/configs/drafts/cancel` | `id`, `expected_version`, `actor` | Отмена автором |
| POST `/admin/configs/drafts/events` | `id` | События с историческими снимками |

Ответы списков и событий содержат массив `items`. Необязательные поля (например,
`active_draft_id` у `current` без драфта) могут отсутствовать.

`current.version` передается в `create.expected_config_version`: если конфиг изменился,
пока пользователь работал в редакторе, создание возвращает 409. При наличии
`active_draft_id` админка должна открыть существующий драфт вместо создания нового.

Для отката создайте драфт с `source_revision` вместо `value`. Из этой исторической
ревизии берется только указанный конфиг, проверяется по текущей схеме, затем действует
обычное подтверждение. `source_revision: 0` означает дефолт текущей схемы; это не
историческое значение дефолта на момент первой установки.

Ошибки: 400 — невалидное тело/значение, 403 — чужая правка/отмена или самоподтверждение,
404 — отсутствующий драфт/ревизия, 409 — активный драфт уже существует, устарела версия
или драфт закрыт. Ответ содержит `error` и `message`; неуспешная операция не изменяет БД.

### Пример

```sh
curl -sS http://127.0.0.1:8092/admin/configs/current \
  -H 'Content-Type: application/json' -d '{"config_name":"SHIPMENT_TERMS_CONFIG"}'

# expected_config_version берется из предыдущего ответа.
curl -sS http://127.0.0.1:8092/admin/configs/drafts/create \
  -H 'Content-Type: application/json' \
  -d '{"actor":"author","config_name":"SHIPMENT_TERMS_CONFIG","expected_config_version":0,"description":"Новые условия","value":{"clauses":[],"default":{"is_enabled":true,"max_days":60}}}'

# id и expected_version берутся из ответа создания/редактирования.
curl -sS http://127.0.0.1:8092/admin/configs/drafts/approve \
  -H 'Content-Type: application/json' -d '{"id":1,"expected_version":1,"actor":"reviewer"}'
```

## Авторизация и прямые записи

По текущему договоренному ограничению `actor` явно передается вызывающим кодом;
это локальная идентификация, а не доказательство личности. Перед внешним доступом
нужно подключить аутентификацию и роли админки. Один префикс `/admin` не заменяет
проверку прав и сетевую изоляцию внутреннего listener.

Прямых ручек публикации и отката нет. Начальные конфиги и локальная smoke-проверка
также создают валидный драфт и подтверждают его от другого actor. История рабочих
ревизий доступна через GET `/admin/configs/history`.

Миграция `V0002__create_config_drafts.sql` добавляет таблицы версий, драфтов и событий.
На существующей базе начальная версия каждого известного сохраненного конфига берется
из последнего снимка; после обновления она меняется только при изменении этого конфига.


Ручки вызывают именованные методы `ConfigStore`: `CreateDraft`, `EditDraft`,
`ApproveDraft`, `CancelDraft`, `GetDraft`, `ListDrafts`. Аргументы и результаты —
обычные структуры из `src/domain/models.hpp`; строкового диспетчера операций нет.
Ошибки `InvalidRequest`, `DraftForbidden`, `RevisionNotFound`, `RevisionConflict`
явно переводятся во view в ответы 400/403/404/409. Неожиданные ошибки хранения
и преобразования данных остаются серверными ошибками, а не ответами 400.

JSONB-документы преобразуются в модели в `src/repositories/draft_document.cpp`.
JSON значений конфигов сохраняется, поскольку их схемы задаются отдельно.
Общие HTTP-модели описаны в `services/configs/docs/api/admin/configs.yaml` в
`components.schemas`. `src/views/models.hpp` преобразует доменные структуры в
сгенерированные DTO; JSON-сериализация списков и вложенных снимков выполняется кодгеном.
Необязательные поля списков, например approved_by до подтверждения, опускаются;
active_draft_id в каталоге явно содержит null, если активного драфта нет.
