# План и факт контейнеров

План принадлежит поставке. Одна активная строка — сочетание типа контейнера и
SOC/COC; повторное добавление такого сочетания увеличивает количество в этой
строке. Команда остаётся идемпотентной. Номера контейнеров план не генерирует.

Факт берётся из Transportations по текущим данным всех контейнерных перевозок
поставки. Способ создания перевозки не влияет на учёт. При изменении типа
контейнера, SOC/COC или типа перевозки результат меняется при следующем чтении.
Поле `item_id` старых перевозок не является источником факта.

- **По плану** — количество в активной строке плана.
- **Созданы** — число контейнерных перевозок с совпадающими типом и SOC/COC.
- **Создаются** — остаток незавершённых операций, ещё не материализованный в
  Transportations. Уже созданные перевозки повторно не учитываются.
- **Осталось** — максимум из нуля и разности плана, факта и создаваемого остатка.
- **Превышение** — максимум из нуля и разности факта и плана.

Превышение не запрещает создание перевозок или уменьшение плана, в том числе
до нуля. Редакции и ключи идемпотентности продолжают защищать команды от случайных
повторов и потери конкурентных изменений.

Контейнерные перевозки с заполненными признаками, для которых нет строки плана,
показываются как «Вне плана». Если не заполнен тип контейнера или SOC/COC,
показывается отдельный счётчик и раскрываемый список с постраничной загрузкой.
Другие типы перевозок в контейнерном плане не учитываются. Отключение планирования
в настройках организации скрывает раздел, не удаляя перевозки и сохранённый план.

## Чтение и масштабирование

Shipments читает план и незавершённые операции одним снимком своей БД, закрывает
транзакцию и делает один запрос в Transportations с токеном пользователя.
Для агрегата достаточно права `shipments.read` и доступа к организации.
Полные карточки перевозок по-прежнему требуют `transportations.read`.

Transportations одной SQL-выборкой агрегирует только выбранную поставку внутри
организации. Запрос возвращает группы контейнеров и число материализованных
перевозок по запрошенным незавершённым операциям. Отдельного сетевого вызова на
каждую перевозку или строку плана нет. Индекс начинается с организации и поставки.
Сотни тысяч перевозок всей организации в приложение не загружаются.

Между БД нет общей транзакции: при конкурентном создании данные сходятся на
следующем обновлении. Если Transportations недоступен, API возвращает 503,
а не подставляет нулевой факт. Команды изменения плана возвращают сам план;
актуальные счётчики выдаёт запрос чтения.

## Выкатка

Изменение затрагивает Shipments, Transportations, Web BFF и Web. У Shipments и
Transportations есть новые миграции. Старые одинаковые строки плана объединяются:
количества складываются, редакция общей строки увеличивается. Остальные строки
сохраняются архивными для ссылок истории и payload уже созданных операций.
Старые SQL-типы и запросы счётчиков по успешным операциям удалены.

Контракты ответов изменены согласованно: для текущего staging используйте Deploy all
после публикации образов из main. Схемы SQL и контрактов со старыми бинарниками
этого изменения не рассчитаны на совместную работу. Серверная выкатка не выполняется
при локальных проверках.
