# Договоры компаний

Contracts владеет договорами и историей их редакций. Стороны — UUID собственных юрлиц
и контрагентов из Counterparties в той же организации. Банковские счета также остаются
в Counterparties: межсервисных FK и копирования банковских реквизитов нет.

## Первая версия

- Номер договора вводится вручную; одинаковые номера допустимы.
- Собственное юрлицо и контрагент обязательны и должны быть разными.
- Дата договора обязательна; «Действует до» необязательна и не раньше даты договора.
- Даты представлены календарным типом Date в C++, DATE в PostgreSQL и CalendarDate в форме.
- Валюта — код ISO из списка с поиском. Счета сторон необязательны, но выбранный счёт
  должен принадлежать стороне, быть действующим и иметь валюту договора.
- Отсрочка — целое количество дней: null означает «не указана», 0 — «без отсрочки».
  Пока это реквизит договора, расчёта даты оплаты и денежных обязательств нет.
- Примечание можно очистить. Договор можно архивировать и восстановить; физического
  удаления API нет.

При сохранении Contracts проверяет стороны и счета через API Counterparties до начала
транзакции. Проверка описывает состояние на момент ответа справочника; распределённой
транзакции нет. Последующее архивирование компании или счёта не удаляет договор.
Карточка отображает текущие названия и банковские реквизиты. Для будущих счетов/актов
потребуется фиксировать реквизиты, использованные при оформлении документа.

`POST /api/v1/contracts/save` принимает полную карточку с `expected_revision`: 0 для
создания, текущую редакцию для изменения. Пропущенные поля не заменяются пустотой:
необязательные значения передаются явно как null. INSERT/UPDATE возвращает сохранённую
карточку; запись и снимок истории атомарны. Конкурентный конфликт возвращает 409.
История хранится в `contract_history`; отдельного экрана истории в этой версии нет.

## Реестр и права

Реестр использует общий QueryBuilder, каталог RegistryField, фильтры в столбцах,
типизированный курсор и ограниченные страницы до 100 записей. Доступны фильтры по номеру,
обеим сторонам, обеим датам, валюте и архивному состоянию. Названия юрлиц для фильтров
разрешаются общим lookup Counterparties; строки реестра получают названия пакетно.
Номер сортируется с учётом числовых частей. Неуказанный срок в порядке сортировки
приравнивается к 31.12.9999; само поле остаётся NULL. Второй ключ порядка — UUID.

- `contracts.read` требует просмотра контрагентов.
- `contracts.write` требует просмотра договоров и банковских счетов.

Каталог прав регистрируется обычным механизмом релиза. Существующим ролям права
не назначаются автоматически. UI открывается в разделе «Договоры»: реестр, карточка
для чтения и отдельный режим редактирования. Web BFF сохраняет явные view.
