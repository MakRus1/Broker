# Реквизиты контрагентов из DaData

В форме контрагента введите российский ИНН и нажмите «Найти реквизиты».
Поиск возвращает головную организацию или ИП. Филиалы пока не поддерживаются.
Кнопка «Заполнить по ИНН» сразу подставляет найденные реквизиты в форму;
роли и контакты остаются прежними. Существующие реквизиты заменяются результатом поиска. Сохранение выполняется
обычной кнопкой карточки. Поиск не создаёт записей и не пишет бизнес-аудит.
Для иностранных компаний остаётся ручной ввод.

API: `POST /api/v1/counterparties/lookup`, тело `{"tax_id":"7707083893"}`.
Нужно право `counterparties.write` и доступ к выбранной организации.
Проверяются длина и контрольные цифры ИНН. Пустой список означает отсутствие результата.
Недоступность, лимит или ошибка ответа DaData возвращают 503 с безопасным сообщением.
Повторных внешних запросов автоматически нет; таймаут задаётся в компоненте `dadata`
статического конфига Counterparties (`timeout-ms`, по умолчанию 3000).

Используется [официальный API findById/party](https://dadata.ru/api/find-party/).
Нужен API-ключ; Secret key не используется. Срок актуальности данных зависит от DaData.
Статус организации показан для проверки пользователем и сам по себе не запрещает подстановку.

## Локальный Docker-стенд

В `.local/dadata.env` сохраните строку `DADATA_API_KEY=<ваш API-ключ>`.
Файл исключён из Git вместе с `.local`; установите права `chmod 600 .local/dadata.env`.
Не передавайте ключ в командной строке или в чат. После обновления исходников:

```bash
.venv-gen/bin/python scripts/local-env.py status
# Пересоздаём контейнер, чтобы подхватить env_file; restart недостаточно.
docker compose -f .local/compose.yaml up -d --no-deps counterparties
```

Используется необязательный `env_file` Docker Compose (нужен Compose 2.24+).
Без файла приложение запускается, а поиск сообщает, что интеграция не настроена.
При нативном запуске передайте ключ через переменную окружения `DADATA_API_KEY`.
Ключ не встраивается в фронтенд, config-vars или release.json.

## Staging

Deployment Counterparties читает `DADATA_API_KEY` из необязательного Kubernetes Secret
`counterparties-dadata`, ключ `api-key`, в namespace приложения. Создайте или обновите
Secret на VM перед Deploy infrastructure; значение не нужно передавать в GitHub.
Например, в Bash на VM (ввод скрыт, ключ не попадает в историю команд):

```bash
read -rs -p 'DaData API key: ' dadata_key; echo
printf '%s' "$dadata_key" | sudo k3s kubectl -n broker-staging create secret generic counterparties-dadata --dry-run=client -o yaml --from-file=api-key=/dev/stdin | sudo k3s kubectl apply -f -
unset dadata_key
```

Проверьте имя namespace на своём стенде. Манифест с ключом передаётся сразу в kubectl
и не выводится на экран.
После изменения Secret перезапустите Deployment Counterparties: переменные окружения
подхватываются при старте процесса. Обычный CD не меняет и не удаляет этот Secret.

## Совместимость

Миграция `V0009__add_counterparty_kpp.sql` добавляет nullable КПП без заполнения
пустыми строками и новый composite `counterparty_v4`; существующий `v3` сохраняется.
Старые поды продолжают работать с v3 и при обновлении остальных реквизитов не стирают КПП.
В истории до появления КПП поле отображается как «Не сохранено».

В testsuite DaData всегда мокируется; настоящий API-ключ и доступ к интернету не нужны.
