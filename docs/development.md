# Окружение разработки

## Зафиксированные версии

- userver 3.2, commit `19472cc41deda3fb1c7aa7d13d53235a0161a224` и SHA256 архива.
- C++20; основной Linux-компилятор Clang 18.
- CMake 3.31.6, Ninja 1.11.1.4 в общем контейнере; минимум CMake для проекта — 3.24.
- Python 3.12 в контейнере, минимум 3.10 для инструментов проекта.
- PyYAML 6.0.2 и pycodestyle 2.12.1 для инструментов проекта.
- Python-зависимости testsuite и генераторов userver закреплены в `tools/python-constraints.txt`.
- Ubuntu 24.04 закреплена по digest; системные пакеты берутся из снимка репозиториев.

`tools/versions.env` — источник версий userver и Python-инструментов. При обновлении
пересоберите общий образ. Существующий системный userver принимается только при точном
совпадении версии. Checkout `third_party/userver` дополнительно проверяется по commit
и отсутствию изменений отслеживаемых файлов.

## Linux и Docker

`make docker-image` собирает `broker-dev:userver-3.2`. Контейнер работает от пользователя
`builder`, потому что PostgreSQL testsuite нельзя запускать от root. В образе установлены
обе конфигурации userver — Debug и Release; для ASan/UBSan фреймворк собирается из
исходников с теми же санитайзерами, что и приложение. На Linux при проблемах
с правами задайте владельца рабочего каталога под uid 1001 или используйте Dev Container.
На macOS shared mount Docker Desktop обычно обеспечивает доступ без смены владельца.
`make docker-*` хранит `.venv-gen` и каталоги сборки в отдельных Docker volumes для каждой
платформы: Linux не использует нативные файлы macOS. Dev Container также имеет отдельные volumes.
Для проверки amd64 на ARM задайте `DOCKER_PLATFORM=linux/amd64` при сборке образа и запуске
проверок; это использует эмуляцию и может работать существенно медленнее.
Образ с общим тегом необходимо пересобирать при смене платформы.
Служебный порт привязан к loopback внутри контейнера. Для его просмотра используется
Dev Container port forwarding; наружу его публиковать не нужно.

Для Docker Engine на Linux используется host network. На Docker Desktop host networking
нужно включить для сценариев с локальным PostgreSQL; тесты с собственным PostgreSQL работают
внутри одного контейнера. На Windows выполняйте команды из WSL2.

## macOS

1. Установите Command Line Tools: `xcode-select --install`.
2. Установите Homebrew с официального сайта https://brew.sh.
3. Выполните `scripts/install-deps-macos.sh`.
4. Добавьте Python 3.12 и PostgreSQL 16 в PATH, как указано в README.
5. Запустите `make doctor`, затем `make gen`, `make test-debug`, `make test-release`.

CMake автоматически добавляет пути Homebrew к OpenLDAP, PostgreSQL 16, OpenSSL 3, ICU, gettext, zlib и bzip2.
Для совместимости с userver 3.2 Protobuf, gRPC, Abseil и fmt на macOS собираются
из закрепленных исходников фреймворка. CMake и Ninja запускаются из `.venv-gen`,
поэтому версия CMake из Homebrew не влияет на команды `make`.
Нативные пакеты Homebrew обновляются независимо: это удобное окружение разработки,
а воспроизводимость релизной сборки обеспечивает контейнер. Совместимость конкретного
набора macOS-пакетов подтверждается только успешной сборкой.

## Повседневная работа

Изменили спецификацию — выполните `make gen SERVICE=<имя>` и сохраните handler-блок,
lock-файл и заготовки ручной реализации. Сборка отслеживает зависимости спецификаций
и генератора; повторная ручная конфигурация CMake не требуется.

`make test-tools` проверяет инструменты без сборки userver. `make test-debug` строит
C++ и запускает unit/functional tests. `make test-all-release` проверяет все сервисы.
`make new-service` не перезаписывает существующий сервис и откатывает регистрацию
при ошибке. Одновременное создание сервисов блокируется файлом `.service-create.lock`.
После аварийного завершения проверьте изменения и удалите оставшийся lock вручную.

Секреты передаются переменными окружения, например `DB_CONNECTION`. Значения testsuite
предназначены только для локальной БД. Тестовые ручки отключены в обычном config_vars.
`http-client-core` работает во всех режимах; выключать его по тестовому флагу нельзя.

В Linux используется Protobuf 3.21 из закрепленного снимка Ubuntu, в macOS — Protobuf 5.26 из исходников userver. В `tools/python-constraints.txt` соответствующие версии Python Protobuf и gRPC закреплены маркерами платформы.

В dev-образе задано `USERVER_ENABLE_STACK_USAGE_MONITOR=0`: необязательный монитор стека корутин требует `userfaultfd`, запрещенный обычным Docker. Логи, трассировка, Prometheus и санитайзеры продолжают работать; дополнительные привилегии контейнеру не нужны. В среде с доступным `userfaultfd` монитор можно явно включить переменной окружения.
