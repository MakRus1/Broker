# Финансовые метки

Finance владеет справочником финансовых меток организации. Метка описывает вид будущего
дохода или расхода: название, направление (доход, расход, оба), единицу расчёта,
валюту и НДС по умолчанию, примечание. Это справочник; начислений, счетов и платежей
на этом этапе нет. Конкретные доходы/расходы будут хранить выбранные условия отдельно:
изменение значений справочника не должно переписывать уже оформленные записи.

## API и хранение

`POST /api/v1/financial-labels/save` сохраняет полную карточку с `expected_revision`:
0 для создания, текущую редакцию для изменения. INSERT/UPDATE возвращает сохранённый
объект без дополнительного SELECT; изменение и снимок истории атомарны. Конфликт
UUID при создании или редакции при изменении возвращает 409.

`get`, `list` и `filter-values` используют те же права организации. Реестр использует
общий QueryBuilder, серверные фильтры столбцов, сортировку и курсор с проверкой области
запроса. Страница ограничена 100 записями. Названия направлений и единиц доступны
в вариантах фильтра на русском; сортировка этих столбцов учитывает отображаемые названия.

Направления и единицы описаны enum-моделями в OpenAPI. В первой версии единицы:
контейнер, перевозка, тонна, сутки, штука. Пользовательского справочника единиц пока нет.
Название очищается от пробелов по краям; пустое название запрещено. Повтор названия
допустим: идентичность определяется UUID, а условия могут различаться.

`vat_mode = exempt` означает «Без НДС», ставка при этом null. `vat_mode = rate`
требует `vat_rate_basis_points`, включая 0 для ставки 0%. Ставка хранится целым числом
сотых долей процента (2250 = 22,5%) в API, C++ и БД. Допустим диапазон 0–100% и до двух
знаков после разделителя. UI принимает точку и запятую без промежуточного float.
Справочник не определяет применимость налоговой ставки к конкретной операции.

Архивирование и восстановление сохраняют UUID. Физического удаления API нет.
Будущий выбор меток в финансовых операциях должен исключать архивные метки;
старые ссылки на них остаются действительными. Снимки `financial_label_history`
содержат редакцию, автора и время. Отдельного экрана истории пока нет.

## Доступ и интерфейс

- `finance.read_financial_labels` — просмотр справочника.
- `finance.write_financial_labels` — изменение, требует просмотра.

Эти права не предоставляют доступ к будущим доходам, расходам или платежам.
Каталог регистрируется при релизе; существующим ролям права не назначаются автоматически.
В Web есть раздел «Финансовые метки»: реестр, карточка для просмотра, отдельное
редактирование, предупреждение о несохранённых изменениях. Фильтры и расположение
столбцов сохраняются для пользователя. Contracts и Counterparties сохраняют своих владельцев данных.

## Начисления поставки и перевозок

Finance владеет начислениями. У каждой строки есть организация, поставка и необязательная
перевозка. Отсутствие перевозки означает собственную строку поставки. Связь перевозки с
поставкой проверяется через Transportations; перенос сохранённой строки на другой объект
не допускается. Все обращения к зависимостям выполняются до начала SQL-транзакции.

В строке сохраняются метка, направление доход/расход, контрагент, необязательный договор,
единица расчёта, количество, цена, валюта, режим цены, НДС и примечание. Договор проверяется
на соответствие контрагенту и валюте. Названия и рассчитанные суммы сохраняются снимком:
изменение справочника само по себе не изменяет существующее начисление.

Количество передаётся в тысячных долях (до 10 000 единиц), цена — в сотых долях валюты
(до 1 000 000). API принимает только целые числа. Расчёт использует int64_t в проверенном
диапазоне без float: сначала округляется количество × цена до копейки, затем НДС.
Округление половины — вверх. Для цены без НДС налог прибавляется к базе; для цены с НДС
налог выделяется из итоговой суммы. «Без НДС» отличается от ставки 0%. Все валюты в этом
MVP используют два знака после запятой; валюты с другой точностью потребуют расширения.

Список отдаёт только строки выбранного объекта, с курсором по UUID. Итоги рассчитываются
по всем действующим строкам, независимо от страницы. В поставке три группы: собственные
строки, строки перевозок и общая сумма. Каждая строка входит в общую сумму один раз.
Валюты не суммируются между собой; курсы и пересчёт не входят в этот этап. Агрегированные
суммы передаются десятичными строками в сотых долях валюты, чтобы JavaScript не терял
точность больших итогов. Список и итоги читаются в одном снимке REPEATABLE READ.

Архивные строки видимы по отдельному переключателю и исключены из итогов. Изменение
проверяет редакцию (CAS), запись и снимок истории атомарны. Права `finance.read_entries`
и `finance.write_entries` выдаются вручную. Право изменения включает доступ к справочникам,
необходимым для заполнения; одно право просмотра начислений не даёт права их изменять.

Счета на оплату, оплаты, курсы валют и распределение суммы строки между перевозками
не входят в этот этап.
