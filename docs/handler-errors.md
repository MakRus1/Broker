# Ошибки HTTP-ручек

Ожидаемые ошибки сервиса наследуются от `platform::http::HandlerError<Status>`.
Например, сервисный псевдоним `ApiError<409>` хранит код ошибки и сообщение для
пользователя. Для повторяющейся бизнесовой причины можно объявить именованный
класс, производный от этого типа.

```cpp
if (!invoice.has_value())
    throw ApiError<404>{"invoice_not_found", "Счёт не найден"};
```

Сгенерированный handler перехватывает ошибку только тогда, когда соответствующий
статус объявлен в OpenAPI и ответ содержит обязательные строковые поля `error`
и `message`. Ограничения длины этих полей допускаются. Дополнительный catch
в каждой view не нужен. Контракт ручки и тесты описывают ожидаемые сценарии.

Ошибки с необъявленным статусом и неожиданные исключения не перехватываются
этим механизмом и доходят до стандартной обработки ошибок userver (500).
Не следует превращать любое исключение в 400 или 409.

Локальный catch остаётся для содержательной обработки: например, преобразования
конкретного ограничения PostgreSQL или ошибки внешней зависимости. Чтобы
сохранить любую уже сформированную ожидаемую ошибку при таком преобразовании,
можно поймать `HandlerErrorBase` и выполнить `throw;`, не теряя исходный тип.

Решение о повторе запроса принимает вызывающая сторона. Конфликт редакции
обычно требует перечитывания данных и согласования изменений.
