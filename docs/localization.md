# Локализация интерфейса

Каталоги `frontend/shared/i18n/ru.ts` и `en.ts` содержат переводы по постоянным
ключам. Русский каталог задаёт TypeScript-тип `MessageKey`; английский обязан
покрыть те же ключи. Пользовательские данные не являются ключами и не переводятся.
Тексты выводятся React как обычный текст, без HTML.

В компоненте Web используется `const {translate} = useLocalization()` и
`translate('action.refresh')`. Для параметров: `translate('common.loaded', {count: 42})`.
Добавление текста: завести ключ в обоих каталогах, использовать его в компоненте;
проверки контролируют одинаковые параметры переводов.

Выбор «Системный / Русский / English» сохраняется в User Preferences отдельно
для пользователя и организации. Язык браузера учитывается до ручного выбора;
среди неподдерживаемых языков выбирается первый поддерживаемый, иначе русский.
На страницу входа передаётся стандартный OIDC-параметр `ui_locales`.

Первый этап покрывает навигацию, стартовый экран, служебные названия вкладок,
переключатели языка/темы, настройки столбцов и основные действия реестров поставок
и перевозок. Остальные формы, сообщения API и форматирование данных переводятся
следующими этапами. Полный перевод приложения на английский пока не заявляется.

Следующие шаги: перевод форм по разделам; терминология организаций (например,
«поставки/букинги») через отдельные семантические ключи и формы слов; публикация
переводов без релиза. Каталоги сейчас поставляются с фронтендом — новый сервис
переводов и административный редактор в этом этапе не добавляются.

Общие реестры используют переводы интерфейса фильтров, сортировки, выделения строк,
настроек и заголовков столбцов. `registryLabels.ts` связывает стабильные идентификаторы
полей и системных значений с ключами переводов. API передаёт только метаданные:
`id`, `kind`, `sortable`, `case_insensitive` и необязательный `lookup`. Подпись
добавляется на фронте через `localizeRegistryFields`; для номеров учитывается реестр
(поставка, договор, счёт или платёж). Если новый идентификатор ещё не известен фронту,
до добавления перевода показывается сам идентификатор. Поле `label` остаётся только
у вариантов значений: там оно содержит название выбранного объекта или значения.
Названия компаний, номера, пользовательские статусы и прочие данные не переводятся.
Компонент даты переводит подписи и сообщения, сохраняя текущий формат ввода и контракт дат.

Общий заголовок `RegistryHeading` принимает название, количество записей, состояние
загрузки, настройки столбцов и бизнесовые действия. Кнопки настройки столбцов и
обновления, их порядок, размеры и тексты принадлежат компоненту. Все основные
Web-реестры используют этот заголовок вместе с `RegistryTable`; размещать настройки
столбцов вручную в панели фильтров больше не нужно. Стили находятся рядом с компонентом
в `shared/ui/registryHeading.css`.

Каждый столбец задаёт обязательный типизированный `labelKey`. Например,
«Сумма с НДС» отличается от общего поля суммы. Идентификатор столбца и сохранённые
пользовательские настройки при этом не меняются. Проверки охватывают переводы
скрытых стандартных столбцов, использование общего заголовка и отсутствие русских
строк в общих UI-контролах вне каталогов.

Подпись столбца задаётся обязательным `labelKey` в `RegistryColumn`. `id` используется для данных, фильтрации и сортировки; таблица и настройки столбцов переводят только явный ключ, без подбора подписи по `id` или текстового `label`.

Карточка и форма поставки локализованы, включая морские и авиаучастки,
плановые контейнеры и список перевозок поставки. Общие поля выбора контрагента,
сотрудника, города, порта и аэропорта используют тот же каталог. Настраиваемые
статусы организации, названия объектов и введённые пользователем данные
показываются без автоматического перевода. Финансовые формы и структурированная история также используют общий каталог.

Служебные сообщения Web, уведомления и ошибки личных настроек используют каталог.
Хранилище настроек сохраняет ключ сообщения, а компонент внутри Localization
переводит его при отрисовке. Для вспомогательных помощников (HTTP, валидация, PDF)
`interfaceText` читает текущий язык из `document.documentElement.lang`;
это значение устанавливает Localization. Подписки и API-запросы от функции перевода
не зависят. Тексты ошибок, присланные API, пока показываются как есть:
их локализация требует отдельного контракта кодов ошибок, без перевода произвольных строк.

Печатная форма счёта, названия PDF и отчёт об ошибках ZIP переводятся на язык
интерфейса. Названия компаний, услуг, номера и банковские реквизиты не переводятся.
Формат дат и точное представление денежных сумм остаются прежними.
