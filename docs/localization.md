# Локализация интерфейса

Каталоги `frontend/shared/i18n/ru.ts` и `en.ts` содержат переводы по постоянным
ключам. Русский каталог задаёт TypeScript-тип `MessageKey`; английский обязан
покрыть те же ключи. Пользовательские данные не являются ключами и не переводятся.
Тексты выводятся React как обычный текст, без HTML.

В компоненте Web используется `const {translate} = useLocalization()` и
`translate('action.refresh')`. Для параметров: `translate('common.loaded', {count: 42})`.
Добавление текста: завести ключ в обоих каталогах, использовать его в компоненте;
проверки контролируют одинаковые параметры переводов.

Выбор «Системный / Русский / English» сохраняется в User Preferences отдельно
для пользователя и организации. Язык браузера учитывается до ручного выбора;
среди неподдерживаемых языков выбирается первый поддерживаемый, иначе русский.
На страницу входа передаётся стандартный OIDC-параметр `ui_locales`.

Первый этап покрывает навигацию, стартовый экран, служебные названия вкладок,
переключатели языка/темы, настройки столбцов и основные действия реестров поставок
и перевозок. Остальные формы, сообщения API и форматирование данных переводятся
следующими этапами. Полный перевод приложения на английский пока не заявляется.

Следующие шаги: перевод форм по разделам; терминология организаций (например,
«поставки/букинги») через отдельные семантические ключи и формы слов; публикация
переводов без релиза. Каталоги сейчас поставляются с фронтендом — новый сервис
переводов и административный редактор в этом этапе не добавляются.
