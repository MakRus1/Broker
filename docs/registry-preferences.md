# Личные настройки реестров

В поставках, перевозках и контрагентах кнопка «Столбцы» открывает личную раскладку:
можно скрывать поля, менять их порядок перетаскиванием заголовков или стрелками и сбрасывать настройки.
При перетаскивании отображается место вставки; у краёв таблицы включается
горизонтальная прокрутка. Клик по заголовку по-прежнему сортирует записи.
Название записи остаётся видимым. Ширина меняется перетаскиванием границы заголовка;
при фокусе на границе доступны стрелки влево/вправо с шагом 20 пикселей.

Раскладка и применённые фильтры/сортировка сохраняются на сервере отдельно
для пользователя, организации и реестра. Локальное хранилище помогает восстановить
настройки до ответа сервера; при недоступности сервера изменения остаются локально.
Курсоры и строки реестров не сохраняются: после перезагрузки запрашивается первая
страница с восстановленными условиями. Даты восстанавливаются как CalendarDate.

## Исходный вид роли

Администратор организации настраивает реестр обычным способом, нажимает
«Вид для роли…», выбирает роль и сохраняет текущие столбцы, фильтры и сортировку.
Настройка принадлежит организации и роли; для разных реестров задаётся отдельно.
Изменения защищены ревизией от перезаписи параллельной правкой.

При открытии Web настройки выбираются в таком порядке: личные, затем вид текущей
роли, затем встроенные. Столбцы и условия наследуются независимо. Вид роли
не копируется автоматически в личные настройки: наследование сохраняется, пока
пользователь сам не изменит соответствующую настройку. Новый вид роли применяется
при следующей загрузке приложения. Существующие личные настройки не заменяются.

Чтение доступно только действующему участнику организации и только для его роли.
Просмотр всех настроек ролей и изменение доступны администратору организации.
Виды не дают дополнительных прав на данные: серверные проверки сохраняются.

## Добавление столбца

Столбцы задаются массивом RegistryColumn: стабильный id, label, начальная width,
render и при необходимости sort. Значение sort — поле существующего серверного API;
наличие колонки само по себе не добавляет серверную сортировку.
Новый id автоматически добавляется в конец личной раскладки, удалённые id игнорируются.
Для столбца идентификации записи задаётся required. Настройки не управляют правами
доступа и не заменяют серверную проверку разрешений.

Общий RegistryTable формирует заголовки и ячейки в одном порядке и сохраняет
кликабельность строки. Встроенная таблица перевозок внутри поставки использует
собственную временную раскладку и не меняет личные настройки основного реестра.
