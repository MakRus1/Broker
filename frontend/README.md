# Структура фронтендов

`web` — пользовательское приложение, `admin` — админка. Они собираются независимо.
`frontend/shared` содержит код, который действительно используется обоими приложениями
(сейчас — справочник валют). Здесь нет зависимости от React или конкретного приложения.

Внутри `web/src` и `admin/src`:

- `app` — запуск приложения, маршрутизация, рабочие вкладки, сессия приложения и
  композиция разделов. Точка входа — `app/main.tsx`.
- `features` — функциональные разделы: поставки, перевозки, контрагенты, договоры,
  финансы, организации, конфиги и справочники. Компоненты, модели, запросы и тесты
  раздела лежат рядом.
- `shared` — инфраструктура и независимые от разделов элементы: HTTP-клиент,
  тип сессии, UI-компоненты, даты, проверка полей. Этот слой не импортирует
  `features` или `app`.

## Пользовательское приложение

`features/finance` разделён на `services`, `invoices`, `payments` и `labels`.
`FinancePanel` собирает их для поставки, перевозки и самостоятельных услуг.
`features/routes` содержит модели и редакторы участков, общие для поставок и перевозок.
Модели самих поставок и перевозок находятся в `features/shipments/types.ts` и
`features/transportations/types.ts`, а не в HTTP-клиенте.

`features/registry` — общий механизм реестров с фильтрами, сортировкой, раскладкой
столбцов и загрузкой вариантов. Это функциональный модуль, а не чистый UI:
он знает о справочниках и способах получения подписей связанных объектов.
Общая шапка `shared/ui/RegistryHeading` отвечает только за заголовок, количество
записей и расположение действий. Она используется счетами, платежами и услугами.

## Админка

`features/configs` содержит каталог, редактор, историю и сравнение конфигов.
`features/organizations` — организации, сотрудников, роли и настройки организации.
`features/directories` — административные справочники.
Состояние рабочего пространства и связанные с ним вход, уведомления и подтверждение
ухода находятся в `app`; общие элементы выбора и реестров — в `shared`.

## Добавление кода

Новую бизнесовую форму добавляем в соответствующий `features/<раздел>`.
Общий компонент переносим в `shared`, когда у него есть независимый от предметной
области интерфейс. Зависимости между разделами импортируются явно из конкретных
файлов; промежуточных `index.ts` с переэкспортом всех компонентов нет.

Тесты `*.test.ts` / `*.test.tsx` лежат рядом с кодом и автоматически находятся Vitest.
В каждом приложении доступны `pnpm test`, `pnpm build` и `pnpm check-format`.

Существующие стили пока подключаются из `app/style.css`: порядок CSS-каскада сохранён
при переносе. Изменение структуры CSS и унификация стилей двух приложений — отдельная
работа, поскольку одинаковые имена классов сейчас имеют разные оформления.
