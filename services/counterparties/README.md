# Разработка сервиса

Общие инструкции находятся в README корня репозитория и docs/development.md.
В VS Code используйте Dev Containers: Reopen in Container или нативный Clang.

Команды из каталога сервиса перенаправляются в корень монорепозитория:

```sh
make gen
make test-debug
```

Новый API описывается в docs/api. После изменения контракта выполните make gen.
Файлы ручной реализации не перезаписываются; DTO и обработчики создаются в каталоге сборки.
Внутренние /ping и /ping/ready добавляются автоматически при создании сервиса.

Инфраструктура и библиотеки описываются в service.yaml; изменения применяются через make gen.
Структура каталогов: docs/service-layout.md в корне монорепозитория.
Правила manifest и границы генерации: docs/service-manifest.md.


Справочник юридических лиц изолирован по организации. API поддерживает create, get,
list (поиск, роли, архив), update, set-archived, history и lookup по российскому ИНН. Все записи требуют
counterparties.write, чтение — counterparties.read. Для update/set-archived нужна
актуальная expected_revision. Совпадение страны и налогового номера после удаления краевых пробелов
возвращает 409 duplicate_requisites; архивные записи тоже участвуют в проверке.
Роли не ограничивают участие компании в конкретной поставке или перевозке.

История доступна по counterparties.read, изолирована по организации и возвращает типизированные снимки до/после. Новые события сохраняют имя проверенного автора.

Подключение DaData и сценарий заполнения: [реквизиты из реестра](../../docs/counterparty-registry.md).
