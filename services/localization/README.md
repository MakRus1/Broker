# Опубликованные переводы

Сервис хранит общие переводы интерфейса и переопределения организации.
Чтение через `POST /api/v1/localization/catalog` требует Bearer-токена
и действующего членства в запрошенной организации. Web обращается через
`POST /api/localization/catalog` с браузерной сессией и CSRF-защитой.

Запрос содержит `organization_id` и `locale` (`ru` или `en`).
Ответ содержит массив `messages` с парами `key` / `value`.
Каталог организации накладывается на общий по ключу. Пустой каталог допустим.
Пользовательские данные (названия компаний, номера документов) сюда не входят.

Общие каталоги находятся в `localization_catalogs`, переопределения — в
`organization_localization_catalogs`. Публикация заменяет JSON целиком,
увеличивает `revision` и задаёт реальный `published_at`. Размер одного
каталога ограничен 2 МиБ. Редактор и API публикации будут отдельным этапом.
Пока публикация выполняется в БД в одной транзакции.

Например, общие тексты можно заменить следующим запросом:

```sql
INSERT INTO localization_catalogs (locale, messages, revision)
VALUES ('ru', '{"action.refresh": "Обновить данные"}', 1)
ON CONFLICT (locale) DO UPDATE
SET messages = EXCLUDED.messages,
    revision = localization_catalogs.revision + 1,
    published_at = now();
```

Организационная терминология задаётся переводами всех нужных ключей:
например, `nav.shipments`, заголовка карточки, действий и текстов с формами
слова. Изменение одного ключа меняет только соответствующий текст.
Для возврата к общему тексту ключ удаляется из каталога организации.

Web загружает каталог после входа, при смене языка/организации, затем раз
в минуту в видимой вкладке и при возвращении к ней. При сбое остаётся
последний успешно полученный каталог. При смене области кеш очищается,
до ответа используется встроенный перевод. После перезагрузки при
недоступном сервисе также используется встроенный каталог. Гостевая
страница и Keycloak используют публичный `GET /localization/catalog?locale=ru`.
Он читает только `localization_catalogs` и отдаёт ключи `login.*` и `keycloak.*`.
Каталоги организаций в публичном запросе не участвуют. Запрос не содержит
идентификатора организации, cookies или токенов. Web BFF разрешает CORS только
для GET этой публичной ручки.

Адрес каталога в теме Keycloak задаётся переменной `BROKER_LOCALIZATION_URL`.
Локальный и staging-манифесты указывают адрес Web BFF. Тема запрашивает каталог
после загрузки, раз в минуту и при возвращении во вкладку. При ошибке остаётся
последний успешный или встроенный текст. Если ключ удалён из опубликованного
каталога, восстанавливается встроенная подпись.

Для Keycloak поддержаны ключи `keycloak.loginAccountTitle`, `keycloak.username`,
`keycloak.usernameOrEmail`, `keycloak.email`, `keycloak.password`,
`keycloak.doLogIn` и `keycloak.brokerLoginHint`. Обновляются только подписи,
указанные в теме. Пароль, введённый логин, параметры протокола и сообщения ошибок
Keycloak не передаются в Localization. Остальные формы действий Keycloak
(OTP, сброс пароля и т. п.) сохраняют встроенные заголовки.

Фронтенд принимает только известные ключи и строки с тем же набором
параметров (`{count}` и т. п.), что у встроенного текста. Ошибочный перевод
отбрасывается отдельно. Текст выводится обычными React-узлами без HTML.
