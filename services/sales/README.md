# Разработка сервиса

Общие инструкции находятся в README корня репозитория и docs/development.md.
В VS Code используйте Dev Containers: Reopen in Container или нативный Clang.

Команды из каталога сервиса перенаправляются в корень монорепозитория:

```sh
make gen
make test-debug
```

Новый API описывается в docs/api. После изменения контракта выполните make gen.
Файлы ручной реализации не перезаписываются; DTO и обработчики создаются в каталоге сборки.
Внутренние /ping и /ping/ready добавляются автоматически при создании сервиса.

Инфраструктура и библиотеки описываются в service.yaml; изменения применяются через make gen.
Структура каталогов: docs/service-layout.md в корне монорепозитория.
Правила manifest и границы генерации: docs/service-manifest.md.

## История контактов

В карточке работы с клиентом вкладка «Контакты» хранит записи звонков, писем,
встреч и других обращений. Запись содержит дату общения, результат, автора и время
сохранения. Дата общения может отличаться от времени внесения. По клику на запись
можно исправить её поля; автор и время исходной записи сохраняются.

`POST /api/v1/sales/contacts/add` использует `sales.write`, чтение — `sales.read`.
Организация и автор берутся из проверенной сессии. UUID записи служит ключом
идемпотентности: повтор того же запроса не создаёт второй контакт и повторно
не обновляет карточку. Изменённый запрос с тем же UUID возвращает конфликт.

Необязательные `next_action` и `next_action_date` передаются вместе. Они заменяют
следующее действие карточки в той же транзакции, увеличивают её редакцию и
попадают в техническую историю изменений. `expected_revision` защищает от
перезаписи более свежего действия другим менеджером. Контакт без следующего
действия сохраняет текущее действие и редакцию карточки.

Чтение постраничное: 40 записей по умолчанию, до 100 за запрос; порядок — дата
контакта, время сохранения и UUID по убыванию. Курсор ограничен организацией и
карточкой. Незавершённая форма восстанавливается через общий механизм черновиков.

`POST /api/v1/sales/contacts/update` проверяет редакцию контакта, сохраняет новую
версию. Если текущее действие связано с этим контактом, исправление обновит
его в той же транзакции. Ручная замена действия снимает связь; более новое
действие из другого контакта также не перезаписывается. История оригинала и
исправлений доступна через `/api/v1/sales/contacts/history` с `sales.read`.
Существующие записи включаются в историю миграцией.

Срок текущего действия виден в реестре и карточке: просрочен, сегодня или
приближается (следующие три календарных дня). Расчёт идёт по местной дате
пользователя, цвет дублируется текстом.
