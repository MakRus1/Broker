# Запросы ставок

Компонент RFQ принадлежит подготовке продажи: запрос ставок связан с одним участком
входящего запроса. Несколько поставщиков могут дать несколько вариантов, каждый
с набором услуг закупки. Варианты разных участков можно объединять в предложении.

`RfqComponent::Save` проверяет справочники до транзакции. В транзакции блокируется входящий
запрос: создание поставки и правка RFQ не должны расходиться. После проверки
редакции сохраняются RFQ, снимок истории и события для уведомлений. HTTP-вызовы
уведомлений выполняет существующий outbox после коммита.

`RfqComponent::ResolveQuote` разрешает источник из неизменяемой истории RFQ. Импортируются
поставщик, участок, количество, единица и цена закупки выбранной версии; клиент
не может подменить их, передав другое значение рядом со ссылкой. Просроченные
котировки и ставки для изменившегося участка отклоняются. Продажа задаётся
пользователем отдельно. Для ручной правки закупки источник явно отвязывается.

Текущие границы: ручной ввод ответов из переписки; почтовых интеграций и рассылки
запросов поставщикам нет. Напоминания по срокам не включены. Выделение каталога
ставок в отдельный сервис имеет смысл, когда он получит самостоятельный процесс
использования несколькими модулями и интеграции с поставщиками.

Компонент реализован в `src/components/rfq.hpp` и `rfq.cpp`. Публичный заголовок
описывает бизнесовые операции; SQL и детали сохранения находятся в реализации.
Компонент получает PostgreSQL и клиентов контрагентов, сотрудников и финансов
из ComponentContext. Ручки обращаются к нему через Deps, предложения используют
операцию ResolveQuote. Компонент не зависит от общего ResolveDeps сервиса.
