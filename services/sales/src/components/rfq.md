# Запросы ставок

RFQ связан с одним участком входящего запроса. Несколько поставщиков могут дать
несколько вариантов, каждый с набором услуг закупки. Варианты разных участков
можно объединять в предложении.

View загружает входящий запрос, проверяет ввод через rfq_rules::ValidateInput
и явно получает поставщиков и метки из справочников до транзакции. RfqComponent::SaveRfq блокирует входящий запрос, проверяет доступность
редактирования, участок и редакцию. RFQ, история и события уведомлений сохраняются
атомарно. ShipmentDispatcher доставляет уведомления после коммита.

View читает неизменяемую версию через RfqComponent::FindRfqRevision.
Чистая функция rfq_rules::ApplyQuote проверяет и применяет источник.
Импортируются поставщик, участок, количество, единица и цена закупки выбранной
версии. Клиент не может подменить их значениями рядом со ссылкой. Просроченные
котировки и ставки для изменившегося участка отклоняются. Продажа задаётся
отдельно; для ручной правки закупки источник явно отвязывается.

Компонент получает только PostgreSQL из ComponentContext. View передаёт
организацию, автора, ожидаемую редакцию и подготовленные котировки явно.
HTTP-контекста и клиентов справочников в компоненте нет.

Текущие границы: ручной ввод ответов из переписки; почтовых интеграций и рассылки
запросов поставщикам нет. Напоминания по срокам не включены. Выделение каталога
ставок в отдельный сервис имеет смысл при появлении самостоятельного процесса
использования несколькими модулями и интеграций с поставщиками.
