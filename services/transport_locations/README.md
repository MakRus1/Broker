# Разработка сервиса

Общие инструкции находятся в README корня репозитория и docs/development.md.
В VS Code используйте Dev Containers: Reopen in Container или нативный Clang.

Команды из каталога сервиса перенаправляются в корень монорепозитория:

```sh
make gen
make test-debug
```

Новый API описывается в docs/api. После изменения контракта выполните make gen.
Файлы ручной реализации не перезаписываются; DTO и обработчики создаются в каталоге сборки.
Внутренние /ping и /ping/ready добавляются автоматически при создании сервиса.

Инфраструктура и библиотеки описываются в service.yaml; изменения применяются через make gen.
Структура каталогов: docs/service-layout.md в корне монорепозитория.
Правила manifest и границы генерации: docs/service-manifest.md.

## Автоматическое обновление аэропортов

Компонент `airport-sync` загружает CSV [OurAirports](https://ourairports.com/data/)
после запуска сервиса и далее раз в сутки. Источник бесплатный (Public Domain),
обновляется ежедневно и не гарантирует полноту или точность. В импорт входят
`large_airport`, `medium_airport`, `small_airport` с IATA или ICAO. Признак
`scheduled_service` не используется: отсутствие регулярных пассажирских рейсов
не исключает грузовой аэропорт. Вертодромы, закрытые аэропорты и площадки без
этих кодов автоматически не добавляются; ручное добавление остаётся доступным.

Фронтенд ищет в локальной БД, без обращения к OurAirports. Поиск учитывает
название, IATA, ICAO, город и ключевые слова поставщика. В карточке показывается
IATA, при его отсутствии — ICAO. Оба кода хранятся раздельно в `airport_sources`.
`ident` не принимается за ICAO.

Постоянный ID OurAirports определяет стабильный UUID новой записи. При первом
импорте уже существующий аэропорт связывается по точному коду и стране.
Ручные записи, перенесённые справочники и правки администратора сохраняют свои
название, страну, код и состояние архива при последующих обновлениях. Для
автоматически созданных и ещё не изменённых записей эти поля обновляются из
источника. Удаление строки из выгрузки не удаляет аэропорт из Broker.

Полная выгрузка проверяется до записи: обязательные колонки, CSV, ID, коды,
дубли, минимальный объём и сокращение числа аэропортов не более чем на 20%.
Обновление источника и поискового справочника коммитится одной транзакцией.
Любая ошибка оставляет предыдущую версию доступной. Транзакция не удерживается
во время HTTP-запроса и разбора CSV.

Несколько подов координируются через `airport_sync`: атомарно берут аренду на
пять минут, перед публикацией проверяют её под блокировкой строки. После
успеха следующая загрузка назначается через сутки, после ошибки — по истечении
аренды. Компонент проверяет расписание каждую минуту. В `airport_sync` остаются
время успешного импорта, SHA-256 и число записей; ошибки и успешные обновления
видны в логах компонента.

Настройки находятся в статическом компоненте `airport-sync`: `url`, `timeout`,
`minimum-records`. Переменная `airport-sync-enabled` включает компонент через
`load-enabled`; по умолчанию он включён, в testsuite выключен. Функциональные
тесты включают его с локальным mockserver и не ходят в интернет.
