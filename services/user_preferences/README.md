# Личные настройки пользователя

Сервис хранит настройки реестров: столбцы, их порядок и ширину, фильтры и сортировку.
Записи изолированы по организации, issuer и subject из проверенного токена.
Идентификатор пользователя нельзя передать в теле запроса.

- `/api/v1/preferences/list` — настройки текущего пользователя указанной организации.
- `/api/v1/preferences/save` — атомарное создание с `expected_revision = 0` либо
  обновление существующей ревизии. Конкурирующее изменение возвращает 409.

Обе ручки проверяют действующее членство через Organizations. Проверка членства
не заменяет проверку бизнесовых прав. `/api/organizations/access` по-прежнему
требует конкретное право; отдельная `/api/organizations/membership/get` возвращает
только ID организации и не выдаёт разрешений.

Значение — JSON-объект размером до 64 КиБ. Формат настройки и его версию определяет
фронтенд. Например, `shipments:columns:v1`, значение `{"value": [...]}`.
Сервис не интерпретирует поля таблиц; при восстановлении фронтенд проверяет их
по текущему описанию реестра, удаляет неизвестные столбцы и добавляет новые.

В Web используется прежний `useRegistryPreference`. Дополнительный код для
каждой таблицы не нужен. Перед открытием реестров Web загружает настройки;
локальные предпочтения старой версии переносятся только в первую открытую
организацию и только при отсутствии серверного значения. Список уже известных пользователю столбцов также хранится на сервере. При первом
открытии реестра устанавливается исходный список; последующие новые поля помечаются
в меню «Столбцы». Открытие меню подтверждает знакомство с ними.

Локальный кеш разделён
по пользователю и организации. При недоступности сервиса реестры продолжают
работать, отображается сообщение с возможностью повторить синхронизацию.

Новое хранилище запускается как обычный сервис с собственной БД. Ресурсы находятся
в `platform.yaml`; специальные назначения прав пользователям не требуются.
